# نموذج النقاط المعتمد — ٢٥ أكتوبر ٢٠٢٦

هذه القواعد تحل محل مواصفات شراء الجيم للنقاط ومخزون الفروع السابقة:

- صاحب المنصة وحده يبيع ويشحن نقاط المتدرب؛ طلبات شحن المتدرب بإيصال تظل معلقة حتى اعتماد صاحب المنصة.
- لا يشتري الجيم نقاطًا، ولا يحتفظ بمخزون تشغيلي، ولا يبيع أو يشحن لمتدرب، ولا يحوّل نقاطًا بين الفروع أو الرصيد المركزي.
- الجيم يحصل على مستحقات الزيارات وتسوياتها فقط. الحجز وحجز النقاط والتأكيد والإلغاء والتسوية والسحب تستمر بحسب السياسات المعتمدة.
- النقاط الترحيبية متوقفة افتراضيًا. صاحب المنصة يحدد عددها ويشغّلها أو يوقفها من إعدادات التسعير. عند التفعيل تُمنح للمتدرب الجديد أثناء إنشاء الحساب فقط، مرة واحدة، ولا تُمنح عند تسجيل الدخول أو تغيير كلمة السر ولا بأثر رجعي. حساب الجيم لا يحصل على محفظة نقاط ترحيبية.
- الهدية تسجّل بقيد نقاط متوازن وسجل منح فريد للحساب، مع صلاحية ٩٠ يومًا. إيقافها لا يسحب النقاط الممنوحة سابقًا.

## النشر والبيانات السابقة

شغّل migration `202610250001_platform_only_points` قبل تشغيل كود التسجيل الجديد، ثم حدّث الويب وتطبيق Flutter. يجب إعداد سعر النقطة أولًا قبل تفعيل الهدية.

المسارات القديمة للبيع ترفض التنفيذ، ومسارات شراء/تحويل المخزون لم تعد مسجلة. لا تعتمد الحماية على إخفاء أزرار التطبيق. قيد قاعدة البيانات يمنع إصدار أو نقل نقاط جديدة إلى مخزون الجيم والفروع.

السجلات المالية القديمة والأرصدة المخزنية الموجودة قبل هذا القرار محفوظة، ولا تتحول تلقائيًا إلى مستحقات زيارات ولا تُحذف أو تُصفّر. أي رصيد سابق مدفوع يحتاج تسوية موثقة خارج نموذج الشراء الجديد قبل إغلاق حساب الجيم؛ لا يفترض هذا التغيير قرار رد الأموال أو تحويلها. تقارير المبيعات السابقة مخصصة للتاريخ فقط.

## التحقق

- اختبارات API للوصول المتوقف وصلاحيات تسجيل الزيارة وهدية التسجيل.
- اختبارات قاعدة البيانات لتكرار الشحن الإداري والمنح الترحيبية وإيقافها، مع استمرار فحوص سجلات الزيارات والتسويات.
- اختبارات واجهات الويب لاستبعاد البيع والمخزون من أدوار الجيم.
- اختبارات Flutter لإزالة إجراءات البيع والتحويل وعرض المستحقات بالجنيه؛ يلزم تشغيلها على SDK Flutter قبل الدمج.
